# Contributing to Awesome AI Tools

Thanks for your interest in improving this list! This guide explains what we
accept, how to format your submission, and how the review process works.

## TL;DR

1. Fork → branch (`add/tool-name`) → edit `README.md` → PR.
2. One tool per PR, in the correct category, in English.
3. Use the exact entry format below. No marketing copy. No tracking links.

## What we accept

- **Tools with genuine, verifiable value** — products people can use today and
  open-source projects with real adoption or clear differentiation.
- **Actively maintained** projects (meaningful activity within the last 12 months).
- **Any category that already exists** in the README. New categories need at
  least 5 quality entries — propose them in an issue first.

## What we will close

- Thin API wrappers, template clones, and "me-too" tools with no differentiation.
- Entries written as marketing copy ("10x your productivity!", pricing pitches,
  "live in 24 hours").
- Links with UTM parameters or tracking campaigns aimed at this list.
- Bundles of multiple affiliated tools, or submissions made by automated agents
  on behalf of an operator. Submit your own tool, in your own words.
- Non-English entries (the list is English-only for consistency).
- Duplicate or redundant entries (e.g., a second "awesome X" list when one is
  already linked).
- Self-assigned ⭐ or 🔥 badges — those are maintainer-only signals.

## Entry format

List entries:

```markdown
- [Tool Name](https://example.com) — One factual sentence describing what it does and who it's for. `#tag`
```

Table entries follow the existing column structure of the section. Use an em
dash (`—`), not a hyphen, and end with applicable tags.

### Tags

| Tag | Meaning |
|---|---|
| `#opensource` | Source code publicly available |
| `#free` | Meaningful free tier |
| `#selfhost` | Can be self-hosted |
| `#api` | Provides a developer API |

Only use these four tags. Don't invent new ones (`#paid`, `#freemium`,
`#android`, `#oss` will be removed or the PR closed).

### Placement

- Add the entry at the end of the appropriate subsection, unless it clearly
  belongs next to a comparable tool.
- Don't insert entries under a section heading in a way that breaks the list
  structure.
- Don't reorder other entries.

## Review process

- A maintainer reviews every PR. Reviews are manual, so please be patient.
- Descriptions may be lightly edited for tone or length during merge — this is
  normal and not a rejection.
- If your PR is closed, the closing comment will explain why. You're welcome to
  fix the issue and resubmit.

## Reporting stale or broken entries

Open an [issue](https://github.com/shahedbd/awesome-ai-tools/issues) with the
tool name and what changed (shut down, acquired, renamed, or unmaintained).
We remove or annotate stale entries to keep the list trustworthy.
